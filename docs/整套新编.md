# 整套新编

用户给模板和一堆材料（docx / pdf / pptx / md / txt），要一份新的汇报稿。

```text
python scripts/compose.py 模板.pptx 材料.docx [材料2.pdf ...] -o out/汇报/基于模板学习的ppt编制技能介绍.pptx --req "给集团领导汇报 AI 办公成效，12 页左右"
    [--style report] [--resume] [--until S3] [--regen] [--fix] [--no-diagrams] [--config config.yaml]
```

`-o` 的基准名用**封面中文题目**（可先占位，出封面标题后再改成与封面一致）。实际交付文件为 `<基准名>-图片版.pptx` 与 `<基准名>-可编辑版.pptx`，不要用技能英文 id 或内部代号当主文件名。

封面和目录默认必有：模板里有封面页型、能认出条目的目录页型，就各生成一份；模板里没有对应页型就不生成，屏幕输出记 `missing_pages`（如 `["目录"]`），交付说明里必须告诉用户这份稿缺了哪一种、为什么。

成品页 = 模板封面 + 模板目录 + 页纲里的各页（按 `clone_from` 克隆模板样例页）+ 模板致谢页，模板其余样例页删掉。模板在章与章之间也放了目录时，每一章正文前都有一页。

`--req` 同时交给 S1 和 S3：S1 按它决定摘哪些事实（要求里点名的每一部分都要摘到），S3 按它分章（要求里给了章节就照用）。

## 步骤与过程文件

每一步先落在 `汇报-过程/<名>.json`，供下一步读取。两份 pptx 写好后这个目录和 `-图/` 一起删掉，不交给用户。`--until` 停住时保留 `-过程/`：

| 步骤 | 过程文件 | 做什么 | 提示词 |
|---|---|---|---|
| 读材料 | `材料.json` | 各份材料抽成章节与段落，合并 | — |
| 风格卡 | `风格卡.json` | `pptkit/profile.py` 分析模板 | — |
| S1 | `S1_摘要.json` | 材料摘要：主题、关键事实（编号 F1…）、数字（编号 D1…） | `prompts/text/summarize_material.md` |
| S2 | `S2_视觉理解.json` | 视觉模型看模板缩略图，总结页面节奏、图形风格、整体调性，交给 S3；没配 `vision_model` 或失败就跳过。与 S1 并行 | `visual_profile.md` |
| S3 | `S3_大纲.json` | 叙事主线（存在 `narrative`）+ 页纲：封面 `title`（按封面标题框限长），每页 `section`（所属章名，带序号）、`role`、`clone_from`、`text_plan`、`diagrams`（`type`、`description`）。只排正文页，封面、目录、致谢由模板自带 | `outline_narrative.md`、`outline_pages.md` |
| S4 | `S4_页面正文.json` | 逐页撰写 `title`、`intro`、`bullets`、`notes`、`diagram_data`（并发，限流时自动退回串行） | `write_page.md` |
| S5 | `S5_正文_审后.json`、`S5_审查报告.json` | 前后连贯审查：术语、数字这类机械问题直接替换；其余问题（重复、断档、遗漏、过空过满）按页给出修改意见，交回 S4 重写这些页（一轮，并行），报告里 `revised_pages` 记重写了哪几页 | `coherence_check.md`（重写仍用 `write_page.md`） |
| 出图 | `出图任务.json` | 每张图的 diagram（bbox、brief、layout） | `prompts/diagram/generate_svg.md` |

文案提示词都在 `prompts/text/`，代码在 `scripts/text/`（一个步骤一个模块），大模型调用在 `scripts/llm/`。

### 字数怎么定（样例页容量）

S3 之前，`compose.py` 用 `pptkit/autofill.page_capacity` 量出每个正文样例页的原标题、导语框字数和行数（按字号和框宽算每行字数）、每张卡片字数、有没有图区，列给页纲选 `clone_from`；封面标题框能放几个字（`cover_title_room`，不换行的框只有一行）也告诉 S3。页纲出来后 `fit_outline` 按所选样例页改写 `text_plan`：

- 卡片页：要点条数 = 卡片数，每条约等于卡片原字数，不写子要点；
- 单框页（导语和要点都写进一个框）：导语约占四成，要点最多 4 条，合计不超过原框字数；导语和每条要点各占一段、段尾不满也占一行，所以还按行数卡：导语至少一行，要点条数 ≤ 原行数 − 1，每条不超一行。只卡字数时，3 行的框写进导语加 3 条短要点会变 4 行，压到下方图区；
- `max_total_chars` 是全页上限，S4 撰写和 S5 审查都按它控字数。

`clone_from` 不是正文样例页时（比如选了封面），自动换成正文页，要图的优先换有图区的页，并打警告。手改 `S3_大纲.json` 后 `--resume`，会按新的 `clone_from` 重算字数。

### 提示词瘦身的约定

- 注入的数据块（摘要、页纲、正文）用紧凑 JSON（`llm.adapter.as_json`）；
- 页纲只写事实编号（`key_facts_to_use: ["F2","D1"]`），S4 由程序换回原文；
- 字数由程序算（`text.pages.char_count`），不让模型估；
- 结构图修补轮不再附风格范例 SVG（上一版 SVG 已体现风格）。

查看每次调用实际注入了什么：`python dev/tools/prompt_sizes.py out/汇报/汇报-过程 --req "…" --dump out/prompt_dump`（不调模型，用过程文件回放）。

## 调试

- `--until S3`：跑到这一步就停，并留下 `-过程/`。打开 `S3_大纲.json` 改页纲（换 `clone_from`、删页、改 `text_plan`），再 `--resume` 往下跑。
- `--resume`：已有过程文件的步骤直接读，不调模型。要重跑某一步，删掉它和它之后的过程文件。整稿已经写完时过程目录已删除，再跑就是重新生成。
- `--no-diagrams`：只出文字，先看页面排得对不对。
- `--fix` 在当次写 pptx 之前修补没过检查的图。写完后 `-图/` 已删除。

## 文字怎么填进样例页（认槽）

`pptkit/autofill.py` 在克隆来的页上找这几类文字槽：

- **标题**：标题占位符（包括位置继承自版式、页上没写坐标的）；没有就取页面上部 22% 内最靠上、宽度超过页宽 10%、不超过 40 字的文字（「1.1工作要求」这类窄标题只有 15% 宽，标题下方的页签约 7%）。封面放宽到上部 60%、宽度要超过 20%，且只换标题；封面标题按 `fit_cover_title` 收窄到不超过页宽 75%、放不下就按语义断成两行、在原区域上下居中（细则见 [文案与目录.md](文案与目录.md)「封面标题」），报告记 `cover_title`。封面标题以下的组织落款、日期，页纲里写了 `subtitle` 就换上，没写就清掉，避免留下模板原有落款；报告记 `subtitle_cleared`。
- **小节**：标题下方、仍在上部 22% 内的另一行短文字。行业模板常见两级：顶栏写章名「二、……实践情况」，下面写「（一）整体思路」。认出小节时，页纲的 `section` 写顶栏、本页 `title` 写小节；没有小节的模板照旧只写标题。
- **图注**：正文区里没被当成槽的短文字（≤ 30 字），多是旧图旁的说明（如竖排的「智能体数据接入概览」）。这页要清旧图时一起删，报告记 `captions_cleared`。
- **卡片**：宽度不小于页宽 20%、彼此宽差 < 30%、高差 < 20% 的一组文字框（至少 2 个，取最多的一组），按先上后左排序。要点按顺序填进去，只放主句。
- **导语**：其余宽度不小于页宽 30% 的文字里面积最大的。没有卡片时，导语和要点收成一段写在这里，并套风格卡里的正文样式，不沿用框里原来各段不一样的字。
- **备注**：写进备注页。

样例页上的旧示意图（风格卡 `kind=review` 的图片）一律清掉，图区取这些旧图的外接框。顶栏标志、通栏页脚、铺满整页的底图不算进这个框，上方的章名和导语留着。没字、几乎通栏、从标题下铺到页脚上的大底框是正文背景，清图时留下。没有内容图时用正文区右半边。

## 目录页

模板有目录页、且条目认得出（`pptkit/slides.toc_entry_count`：一个「01」这类编号配同一行右侧的章名）时，封面后留第一份。模板里这种目录页出现不止一次（章与章之间也有）时，每一章正文前都再放一页。`fill_toc` 按页纲各页 `section` 去重后的顺序重写条目。每一页都标出这一页后面的那一章：模板里出现少的那套样式是当前章，出现多的是其余章（字色、填充都跟着这套走）。只有一套样式时无法区分，报告里仍记下 `current`。

- 条目排好后整组上下居中（`slides.center_toc`）：对齐左侧「目录 / CONTENTS」的纵向中心，认不出时对齐页面中心；报告 `toc.centered` 记平移量。条目变少时不能还从模板顶部排起；
- 以第一行条目为样板克隆，行距取原行距，章多时在原条目区到页面 85% 之间均匀压缩，报告 `toc.crowded` 表示比编号徽标还挤；
- 编号已在徽标里，章名去掉「一、」这类序号；按字号估算一行放不下时去掉末尾括号注释，仍放不下记 `toc.too_long`；
- 克隆时去掉插件写的形状标签（`p:custDataLst`）：一个标签部件只能被一个形状引用，共用会让 PowerPoint 打不开文件，`validate_deck` 查不出来。

条目认不出的目录页（比如整页是一张图）直接删掉。

目录当前章高亮必须「强调填充 + 对比字色」成套；克隆条目后若同时存在 `noFill` 与 `solidFill`，去掉 `noFill`（`slides._sanitize_sp_fill`）。

正文样例页顶栏/侧栏的旧章节导航（页签）在填字后改成新大纲章名并按 `section` 高亮，见 [文案与目录.md](文案与目录.md)。

## 报告

脚本打在屏幕上的结果里，`filled` 按页记录：

| 字段 | 意思 |
|---|---|
| `title` / `subtitle` / `section` / `intro` / `cards` | 填进了哪个形状（`subtitle` 是小节、`section` 是顶栏章名） |
| `bullets_dropped` | 要点比卡片多，没放下的要点 |
| `overflow` | 文字明显长于原槽（超过原字数 1.3 倍且多 20 字以上），或导语框行数超过原行数，或封面标题超出一行，可能溢出 |
| `captions_cleared` | 随旧图一起删掉的图注 |
| `subtitle_cleared` | 封面上没被替换、因而清掉的组织落款或日期 |
| `notes` | 写了备注 |
| `cover_title` | 封面标题的排法：`lines` 几行、`sz` 字号、`width_ratio` 框宽占页宽、`fits` 是否放下 |

屏幕输出顶层的 `toc` 记目录页：`entries` 条数、`step` 行距、`crowded`、`too_long`、`centered`（整组居中的锚点和平移量）。`missing_pages` 记模板缺的封面或目录页型，非空时写进交付说明。

页纲里同一章平级的小节每个单独成页、用同一类样例页（`outline_pages.md` 第 8 条）。S3 出来后检查一遍：后几项被并成一页纯文字的，拆开、改 `clone_from` 后 `--resume`。

`bullets_dropped` 和 `overflow` 非空时要处理：换一张卡片更多的样例页（改 `clone_from`），或在 `S4_页面正文.json` / `S5_正文_审后.json` 里删短后 `--resume`，或出稿后用 `slides.py duplicate-shape` 加卡片。`diagrams` 里每张图的 `problems` 同加一章。

## 已知局限

- 认槽是按几何规则猜的，版式特别的样例页可能认错；报告里看每页填进了哪个形状，不对就换 `clone_from`。
- 要点多于卡片数时直接丢弃（记在 `bullets_dropped`），不会自动复制卡片。
- 文字超出原槽只报告，不自动缩字号。

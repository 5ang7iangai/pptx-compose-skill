# 模板分析与风格卡

```text
python scripts/profile_deck.py 模板.pptx -o 风格卡.json
```

每次现抽，不把结果留给下一份模板。实现在 `scripts/pptkit/profile.py`。任务脚本（`add_chapter`、`redraw_pages`、`compose`）会自己调用它取主色和字体，不必先手跑；写页纲、选样例页、定 bbox 时手跑一份来看。

## 先看这些字段

- `canvas`：宽高，单位英寸。绘图和摆字都用这个画布。
- `build_path`：`exemplar` 表示样式画在样例页上，克隆样例页；`placeholder` 表示正文页真的用了标题或正文占位，仍克隆一页已用该版式的正文页再改字。没有可克隆的正文页时停下来说明，不从空白版式硬画。
- `fonts.ea` / `fonts.latin`：主题字体。结构图没有单独的图表字体时用 `fonts.ea`。
- `fonts.roles`：从这份模板学出的四类字体，每类一套（东亚字体、西文字体、字号、是否加粗、字色）。`body` 是正文框里最常见的一套，`emphasis` 是其中加粗或另着色的一套，`table` 是表格，`chart` 是图表；图表没有现成文字时沿用正文的字体名。填正文用 `body`。同一类不要混用另一套。
- `palette`：`title` 是标题和顶栏上的颜色，结构图主色优先用它；`dominant` 仍是页上最常见的饱和色，只在 `title` 里没有彩色时才用。`accent` 次强调、`light` 浅底、`surface` 近白、`text` 深色字。`theme.colors` 只作对照。结构图整套色由选定的主色推导（[结构图.md](结构图.md)「配色」）。
- `page_number.on_slides`：为 0 时正文页没有页码占位，不伪造页码。用户明确要求时再补真正的页码字段。
- 目录条目的间距、字号和填充以页面实测为准，不把风格卡里的主色直接铺成新按钮（[文案与目录.md](文案与目录.md)）。

## 每一页

- `role`：`cover`、`toc`、`content`、`ending`。目录和章节扉页都是 `toc`（正文里有「目录」或 CONTENTS；字中间有空格也算）。
- `layout`：版式名称。
- `text_slots`：可替换的文字块，含形状名、全文和位置。
- `pictures`：图片位置、媒体文件名、`kind`、`hint`。定 `diagram.bbox` 就从这里量。
- `has_shape_diagram`：页上已有燕尾、连接符一类形状图。克隆时一起带走，不另铺一张贴图。
- `patterns`：页型聚类。同一组里的页结构接近，用来选「这一节克隆哪一页」。

更细的顶层形状位置：`python scripts/inspect_slide.py 模板.pptx 6 7`。

## 图片 kind

脚本只自动判定有把握的三类：`logo`、`decoration`、`document`，其余是 `review`。`hint` 为 `diagram` 时只说明色块比较像结构图，仍然要看图，看完把 kind 改成下面之一再决定画不画：

| kind | 处理 |
|---|---|
| diagram | 可以重绘成结构图 |
| screenshot | 保持图片 |
| document | 保持图片 |
| logo | 保持图片 |
| decoration | 保持图片 |
| chart | 没有数据表就保持图片；用户给了数据再做成原生图表 |
| review | 保持图片，直到看图后改 kind |

拿不准就保持图片，不把截图标成 diagram。`compose` 例外：样例页上的 `review` 图是旧课题的示意图，内容一定不对，一律清掉换新图。

## 样本核对

模板是「示例业务介绍模板」时，风格卡应满足：画布 13.33×7.50 英寸；中文微软雅黑、西文 Arial；`build_path` 为 exemplar；正文页占位为 0；主题强调色是蓝色，而 `palette.dominant` 不是该蓝色；封面、三份目录、致谢角色正确；第 20 页 `has_shape_diagram` 为 true；封面标识为 logo、封面色带为 decoration。这些是回归预期，不是技能的默认配色。

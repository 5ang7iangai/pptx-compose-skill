你是一名专业的企业汇报材料分析师。请阅读以下材料，提取关键信息，输出结构化的 JSON 摘要。

制作要求（这份摘要要支撑按此要求编写的整套幻灯片）：
{requirement}

材料原文：
{material_text}

═══ 输出要求 ═══

输出严格 JSON 格式，包含以下字段：

```json
{
  "core_proposition": "一句话：这份材料在讲什么、给谁看、要达到什么目的",
  "key_facts": [
    {
      "fact": "可直接引用到幻灯片上的一句话事实",
      "source": "材料中的位置标识（如第N节/第N页）",
      "verified": true
    }
  ],
  "arguments": [
    {
      "claim": "材料的一个核心论点",
      "evidence": "支撑这个论点的具体证据（数据/案例/引文）",
      "source": "材料位置"
    }
  ],
  "entities": ["材料中出现的关键名词：产品名、系统名、机构名、项目名"],
  "data_points": [
    {
      "metric": "指标名",
      "before": "改进前的值（如有）",
      "after": "改进后的值（如有）",
      "source": "材料位置"
    }
  ],
  "missing_info": ["材料中没有提到但汇报时可能需要的信息，如部署时间、投资金额"],
  "audience_hint": "推断的目标读者（从材料用语和结构推断）",
  "suggested_narrative": "建议的叙事类型，如：问题驱动型（痛点→方案→效果）/ 成果展示型 / 技术方案型"
}
```

═══ 提取原则 ═══

1. key_facts 只提取材料中有明确来源的事实，不推测、不编造
2. 数字、百分比、时间必须原文照抄，不做四舍五入
3. missing_info 列出汇报时读者可能追问但材料里找不到答案的信息
4. audience_hint 从材料的用语风格推断（学术/技术评审/领导汇报/客户宣讲）
5. 覆盖要全：后续每页正文只能引用这里的事实。材料的每一章、制作要求里点名的每一部分，都要有支撑它的事实；步骤顺序、清单里的各项名称、规则和取值都算事实，名称原样保留（如流程的每一步分别写一条，可选项逐一列出）。条数随材料篇幅和页数走，几千字以上的材料通常 30 条以上，不要只挑几句总括
6. 如果材料很短（< 500 字），key_facts 和 arguments 可以少，但 core_proposition 必须有
7. 输出纯 JSON，不要加解释文字

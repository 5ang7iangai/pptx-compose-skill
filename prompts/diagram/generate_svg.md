═══ 出图前思考（每张图都要做；想清楚再写 SVG） ═══

把这张结构图当成**一块要上线的 Web / HTML 信息图组件**来设计，而不是「按清单堆几个矩形」。风格与圆角**不要写死成某一种**（不要默认全圆角或全直角）：先服从当次模板样例 + 本页已选定的 `{style_rules}` / `{layout_rules}`，再在该约束内把细节做足。

写代码前，用足够篇幅在内部想清楚（不必写进输出），至少覆盖：

1. **信息架构**：这张图在页里解决什么问题？主路径 / 并列 / 层级 / 对照各自是谁？哪一块是视觉重心（相当于 hero）？
2. **跟模板**：从模板样例读到的圆角、线宽、卡片疏密、箭头、底色层次是什么？本页已选的 layout/style 是否已经对齐？有冲突时以**模板样例 + 本页选定风格规则**为准，不要另起一套皮肤，也不要因为「好看」强行改成圆角科技风或别的流行风。
3. **版式几何**：按 layout 规则落实骨架（中心辐射、色带、漏斗、树、流程、对照等），禁止把任意版式都画成一排相同方块。
4. **视觉层次（像做网页）**：背景 / 分区底托 / 卡片 / 强调块 / 图标与序号的层级；间距节奏（类似 CSS gap）；对齐网格；同级组件规格一致（同级卡片圆角、描边、内边距、字号档位一致——模板是直角就统一直角，是圆角就统一圆角，禁止同级混用）。
5. **组件精致度**：在元素白名单内尽量做细——标题+说明、图标 defs、连线接到边、旁注、淡阴影（若风格允许）、分组框、强调态。空壳卡、悬空箭头、半截留白柱、只有标题没有做法行，都视为未完成。
6. **响应式意识（定宽画布版）**：内容少时放大组件、拉开或居中，不要挤一角；内容多时先加说明行与旁注、再微调块高，**不许缩小字号**、不许编造材料没有的数字。
7. **自检**：像 review 一页 UI——气质是否像本单位模板、layout 几何是否可辨、同级是否统一、信息是否读得完、有无廉价「方块堆」。

- 文字用业务语言，不写「套版、克隆、脚本、落盘、零件」这类制作词。材料里没有的数字不编，确需占位写「待核实」。

═══ 元素约束（转可编辑版要用） ═══

1. 只用这些元素：`rect`、`circle`、`ellipse`、`line`、`path`、`polygon`、`polyline`、`text`、`tspan`、`g`、`use`、`defs`、`marker`、`filter`/`feDropShadow`。
2. 不用 `foreignObject`、`image`、`clipPath`、`mask`、`pattern`、`linearGradient`、`radialGradient`、`style` 标签、CSS class、`textPath`。
3. 颜色一律写成 `#RRGGBB`；阴影只能用 `feDropShadow`，它的 `flood-color` 可以带透明度。
4. `g` 和 `use` 的 transform 只用 `translate(...)` 和 `scale(...)`，不旋转。
5. 图标：在 `defs` 里用 `<g id="ic-xxx">` 定义（以 0,0 为中心，底形和线条按上面的风格要求），再用 `<use href="#ic-xxx" x=".." y=".."/>` 摆放；图标里的 path 可以用曲线和圆弧。图标半径约等于旁边标题字号的 0.8–1 倍；图标整个落在所在卡片内，图标之间不重叠；图标右缘到文字起点至少留半个字宽。一列条目比较多时宁可不放图标，也不要把图标挤成一串。
6. 箭头：用 `<path d="M x1 y1 L x2 y2" .../>` 或 `<line>` 加 `marker-end`；折线箭头用 `M … L … L …`。连线必须真的连到卡片边缘，不悬空。
7. 文字：每个 `<text>` 是一行，自己写 `x`、`y`（基线）、`font-size`、`fill`，需要时写 `font-weight="700"`、`text-anchor="middle"`。不要依赖自动换行，长句自己拆成多行 `<text>`；估算宽度时中文按 1 个字号宽，确保不超出所在卡片。
8. 不要在 SVG 里写图名大标题（PPT 页面已有标题）。

# 结构图

有结构图就**出两套 pptx**，两版来自同一份 SVG，不是画两次：

1. **助手**按 `prompts/diagram/generate_svg.md` 写 SVG → 脚本规整/检查；不过则助手按 `fix_svg.md` 改磁盘文件再检查，留问题最少的一版。
2. 图片版：SVG 按 4 倍导出 PNG，贴在图的位置。
3. 可编辑版：同一份 SVG 逐元素转成 PPT 形状（圆角矩形、圆、带箭头的连接符、自由曲线、阴影、单行文本框），组名「结构图」。

生成时 SVG 和 PNG 先写在 `<原名>-图/`，贴进两份 pptx 后删除。同一次运行里已有 SVG 就复用；要改就在写 pptx 之前 `--fix`。不要只改 pptx 里的形状。

不要用脚本排几个方块代替助手写 SVG。正式稿禁止方块兜底。

## 贴图位置与导语间隙

结构图 bbox 在导语下方应**横向铺满或居中对称**内容区，勿偏在一侧留出大片空白（约占页宽 30% 以上）。时间轴类须左→右一排节点，避免无意图的高低错落。


结构图 bbox 顶边不得伸进导语框，也不得压住因字数超框而溢出的导语文字。新贴图时顶边相对导语有效底边至少留 **0.15 英寸**（`pptkit.layout_check.GAP`）；`add_picture` / `add_editable` 会先检查，不过就抛错。交付时 `validate_deck.py` 全稿扫描同一规则。导语放不下就删短，或加大导语框并下移 bbox，不要把图顶抬进文字区。


## 版式选用优先级（硬性）

新编、加一章、加一页、重画结构图时，**按下面四级依次选用**，不得跳级乱选；每一页在页纲/`diagram` 里写清「来源：模板样例 / 内置库 / 新设计」与选它的理由。

### ① 优先从当次单位模板学习

1. 读风格卡：标出 `kind=diagram` / `has_shape_diagram=true` 的页，以及同 `patterns` 组里已有结构图的正文页。
2. **抽出模板里已在用的结构类型**（并列卡、流程、对照表、中心辐射、分层、时间轴等），记入任务 `run/` 的「模板版式清单」（可写在 `outline` 旁注或 `assemble` 前的短清单）。
3. 色相、圆角、线宽、卡片疏密、箭头画法**跟模板样例**，不要另起一套气质。

### ② 新写 / 新增内容：优先套用模板已有版式

- 整套新编、加章、加页时，信息结构能对上模板已见过的某一种 → **直接套用该种**（几何骨架对齐样例，换字换条目）。
- 这样整稿壳、色、疏密一致，避免「模板页像一套、新页像另一套」。
- 套用时仍须按该版式的 `catalog/layouts/<id>.md`（若已映射）画满信息，禁止缩成一排空方块。

### ③ 模板没有合适的 → 查技能内置库

- 打开 `catalog/layouts/` + `catalog/图库.html`（或 `svg_diagram.py list`），按信息结构对照下表选型。
- 风格用 `catalog/pairing.yaml` 该版式的预置；色相仍跟**当次模板**标题/顶栏，不跟范例 SVG 样品色。
- 内置库有的版式（如 `hub` / `tree` / `tiers` / `cycle` / `funnel` / `pyramid` / `kpi`）**能用就用**，不要因为「画卡片省事」一律改成 `matrix`/`flow`。

### ④ 内置库也没有 → 宿主助手新设计并入库

- 由**宿主助手**（本对话能力）在线设计：可参照公开资料里的信息图/汇报结构思路（如 PPT Master 一类「技能+SVG→形状」的密度与层次），但**色相、字体、圆角、页边距必须与当次单位模板一致**，禁止另套一套皮肤。
- 设计产物是通用版式，不写客户名、课题名、具体数字。
- **必须入库后再出正式图**（见 [SKILL.md](../SKILL.md)「从模板补进预置」）：写 `catalog/layouts/<id>.md`，必要时新 `styles/<id>/`，改 `pairing.yaml`、页纲类型说明，跑 `check_presets.py`，并手改 `catalog/图库.html`（暂无图库重建脚本，可跳过）。未入库不得在成稿里悄悄用一次性怪结构。
- 本技能脚本**不**另配外部模型 API；「在线思考」= 宿主助手完成设计与落盘。

## 多页防单调（硬性）

- **相邻有结构图的正文页**：不得连续使用同一 `layout` id（封面/目录/致谢除外）。
- **整稿有 ≥4 张结构图时**：至少用到 **3 种**不同 `layout`；不得超过一半的图都是 `matrix` 或都是「竖卡横排」的 `flow`。
- **同一 `layout` 在多页出现时**：信息条目数、强调块位置或分区比例须有可见差异，禁止复制粘贴换字。
- 页纲阶段自检：列出各页 `layout` 序列；若连续重复或种类过少，先改选型再写 SVG。
- 出图时必须按所选版式的几何画（中心圆、分层色带、漏斗、树权等），**禁止**把 `hub`/`tree`/`tiers`/`funnel` 等画成一排相同圆角方块。

## 脚本加固（清单 / 多样性 / 入库 / 终检）

```text
# prepare 后自动生成；也可手跑
python scripts/layout_policy.py inventory --style-card run/风格卡.json -o run/模板版式清单.json

# assemble 写完 diagram_jobs 后默认硬检；不过则 SystemExit（--skip-layout-check 可跳过）
python scripts/layout_policy.py check-diversity --jobs run/diagram_jobs.json

# 交付前终检（validate / checks/run_all 加 --run 时会跑）
python scripts/layout_policy.py check-run --run <run目录>

# 走到选用优先级 ④：先脚手架入库，再补规则；图库暂无重建脚本，可手改 图库.html 或跳过
python scripts/layout_policy.py scaffold --id <id> --name "中文名" --when "适用场景"
python scripts/check_presets.py
```

`check-run` / assemble 硬检内容：未知 layout、相邻结构图同 layout、≥4 图少于 3 种、matrix+flow 超过半数。

## 什么内容用什么图

先看信息结构，再按上方优先级选版式。不要每页都堆一排同样的圆角矩形；内容简单却堆出一排空卡片，就是选错了。下表供 **③ 内置库** 对照：

| 信息 | 版式 |
|---|---|
| 三五个并列结果、没有先后 | `matrix`。卡片里要有标题和一行说明，不只写两个字 |
| 两三根支柱共同撑起一句结论 | `pillars` |
| 三四个大数字 | `kpi` |
| 有先后的步骤、有判断 | `flow` |
| 按时间排的里程碑 | `timeline` |
| 做完又回到起点 | `cycle` |
| 左右两种做法、改前改后 | `compare` |
| 上下层、层内若干能力 | `layers` |
| 自下而上的分级部署 | `tiers` |
| 上窄下宽的层级 | `pyramid` |
| 逐级筛掉、转化收窄 | `funnel` |
| 左侧对象 → 中心主体 → 右侧要点 | `hub` |
| 类型 → 内容 → 用途，每行一组 | `pipeline` |
| 一个总称拆成几类，类下有条目 | `tree` |
| 阶段下面挂着一列动作 | 模板里已是燕尾的页沿用原形状，不删成贴图再重画 |

红头文件、系统截图、标识、封面底纹、没有数据表的曲线图保持图片。只有看图后把风格卡里图片 `kind` 定为 `diagram` 的才重绘。

## 风格库与版式库

都在 `catalog/` 下。目录扫描即列出，不必改枚举；整套新编要让新的图形类型用上对应版式，类型写在 `scripts/stages/（compose 路由）` 的 `TYPE_LAYOUT` 和 `prompts/text/outline_pages.md`。

```text
catalog/图库.html                 给人看的风格、版式对照。风格对比.png 只画了最初七种，以图库为准
catalog/styles/<id>/rules.md      风格规则，原样写进提示词
catalog/styles/<id>/example.svg   范例，写进提示词「只学元素用法和气质」
catalog/styles/<id>/style.yaml    名称、一句人话、参照的设计规范、适用场景、硬性检查
catalog/layouts/<id>.md           版式规则（结构）
catalog/pairing.yaml              每种版式的预置风格，以及改稿时还能选的风格
```

`python scripts/svg_diagram.py list` 列出当前全部风格和版式。下表会过时，以命令和 `图库.html` 为准。

| 风格 | 名称 | 一眼能认出来 | 参照 |
|---|---|---|---|
| `rounded` | 圆角卡片 | 白底大圆角，重点一块涂满主色 | Material 3 |
| `square` | 直角线框 | 直角细线，左侧一条色条 | IBM Carbon |
| `flat` | 扁平极简 | 白底发丝边，几乎没有阴影 | shadcn / Geist |
| `consult` | 咨询汇报 | 结论在上，序号下各一条短横线，底部一行「所以」 | 麦肯锡 / BCG 行动标题 |
| `keynote` | 要点页 | 大数字居中，百分号抬高半级，底部至多三条小注 | 发布会、董事会一页一结论 |
| `report` | 行业报告 | 浅底细边，类别分色，箭头较粗 | 机构汇报常用画法 |

版式预置只给助手出 SVG 用；无助手时不得用机械方块交付正式稿。

从模板看出库里没有的结构或画法、或走到选用优先级 ④ 时，按 [SKILL.md](../SKILL.md)「从模板补进预置」写进 `catalog/`，并改 `pairing.yaml`、页纲类型说明（及若有的 `TYPE_LAYOUT`），再跑 `scripts/check_presets.py`；图库对照页请手改 `catalog/图库.html`（技能包暂无重建脚本，可跳过，以目录扫描与 `svg_diagram.py list` 为准）。`checks` 可用的类型见 `scripts/diagram/checks/style.py` 开头。范例 SVG 的元素白名单与现有范例相同。


## 风格先跟模板，再谈 pairing

选 layout / style 的顺序：

1. **先读当次单位模板**样例结构图与正文卡：圆角或直角、线宽、疏密、箭头、底色层次——**模板已有什么，新图就对齐什么**，不要写死「全圆角」或「全科技绿」。
2. 信息结构能对上模板已见过的版式 → 套用该种；对不上再查内置库 + `pairing.yaml` 预置。
3. pairing 的 `default` 只是**缺省建议**。若与模板气质冲突（例如模板全是直角线框，默认却是 rounded），在 `diagram_jobs` 里改选更贴模板的 style，并在 `style_reason` 写「跟模板样例」或「覆盖 pairing 默认：…」。
4. **每一张 SVG 出图前**按 `prompts/diagram/generate_svg.md` 的「出图前思考」做足：用 HTML / Web 信息图的标准做精做细，而不是只换字的方块堆。精致度靠思考与设计，不靠把风格规则写死成某一种圆角。

## 字号、行距与版面（硬性）

- 字号按**幻灯片磅数**给，和原页正文一致：默认正文 12、标题 15、标签 13、旁注 10 磅。原页正文更大时在 spec 或 diagram 写 `"fonts": {"body": 13}`。`diagram/sizing.py` 按「bbox 宽（英寸）× 72 / 画布宽」换算成画布单位写进提示词：画布 1200 宽、图宽 12.4 英寸时 12 磅正文是 16 号字。
- 多行正文行距 1.5 倍字号；一段文字在卡片里上下居中。
- 圆、胶囊里的图示和文字整体在形状里上下居中，离边至少半个字号。
- 左右两部分空隙不超过画布宽 4%，不许出现整条竖向空白。
- 放不下先加大框、压缩留白，不许缩字号，也不要让模型自行删字。`--fix` 修补同样不许删图意里的条目：检查建议缩短时，改成拆行或加宽同排卡片。
- 粗箭头的头部约 2.6 倍线宽，由规整步骤自动处理。

## 配色

`diagram/palette.py` 由模板主色按色相推出整套，换模板不串色：

- 主色：模板标题文字色、标题填充色，以及页面上方通栏的填充色。太浅就压暗到能压白字。标题上没有彩色时，再从常用色里取够深的。
- 深浅、底色、字色、说明字色、细边：同色相按固定亮度和饱和度推出。
- `night`/`night2`/`nightline`/`glow`：深色风格用；`n50`/`n200`/`n500`/`n900`：中性灰。
- `gold` 重点色：模板第二彩色与主色色相差超过 25° 时用它，否则用金色。
- `c2`/`c3`（浅底 `c2l`/`c3l`）：多色编码用，自动挑与主色、彼此色相差 ≥ 22° 的饱和色，不够时用青、橙补。

参考稿按级别或类别分色时，brief 里写 `{c2}`、`{c3l}` 点名。用户不另填主色。

## 做图的顺序

1. 按「版式选用优先级」选型，在页纲里写明来源（模板样例 / 内置库 / 新设计）与理由；并核对「多页防单调」。**style 跟模板样例**，pairing 默认可覆盖。
2. 写 `diagram`（字段见 [spec.md](spec.md)）：bbox 量旧图位置；brief 写每个分区、每块的标题和一句说明、先后关系，写清高度预算和各块宽度占比；没有的数字写「待核实」。
3. **出图前思考**（见 `generate_svg.md`）：按 Web/HTML 信息图标准想清层次、对齐、同级规格与重心，再写 SVG——做精做细，不写死某一种圆角/流行风。任务脚本会拼提示词；单张调试：

   ```text
   python scripts/svg_diagram.py prompt --brief 图.json --style-card 模板.pptx          # 只看拼好的提示词
   python scripts/svg_diagram.py gen    --brief 图.json -o 图.svg --style-card 模板.pptx  # 只打印提示词 exit 2，不调模型
   python scripts/svg_diagram.py check  图.svg --brief 图.json                           # 带 --brief 才查字号和画重
   python scripts/svg_diagram.py fix    图.svg --brief 图.json -o 图2.svg                # 只打印修补提示 exit 2；由助手改写 SVG
   python scripts/svg_diagram.py png    图.svg -o 图.png
   ```

4. 打开 PNG 看。检查查不出的（箭头方向反了、模块画重、留白不匀、图标太小），把意见写成可执行的数（字号、框高、间距、哪几条要写全）放进 `feedback`，再 `--fix`；有 feedback 时原图不参与择优。改好用 `edit_spec.py --clear` 清掉。大改就改 brief 后 `--regen`。只差几个像素可直接改 SVG。
5. 两版逐页导出对比（[校验与验收.md](校验与验收.md)），应几乎一样。

## 检查查什么

`diagram/checks/` 返回中文问题清单，带坐标和要挪的量，交给助手按 `fix_svg.md` 改磁盘 SVG：

| 模块 | 查 |
|---|---|
| `__init__`（structure） | viewBox 从 0 0 起、元素白名单、不用 class、文字不少于 6 行 |
| `style` | 风格硬性要求（`style.yaml`） |
| `text` | 正文字号低于要求、任何字小于旁注下限、多行正文行距小于 1.35 倍、文字出画布、同一句话（4 字以上）比图意里多就算画重（续行不算）、文字互压、左右贴太紧 |
| `layout` | 圆内文字出圆或整体偏上偏下、粗线压字、竖向空白带、图标压字、文字超出或骑在卡片边线、文字伸进旁边的框、卡片越出分区、图标重叠或伸出卡片 |

## SVG 约束

只用 `rect`、`circle`、`ellipse`、`line`、`path`、`polygon`、`polyline`、`text`、`tspan`、`g`、`defs`、`use`、`marker`、`filter`/`feDropShadow`。不用 foreignObject、image、clipPath、mask、渐变、class 和 style 标签，否则转不成形状。图标在 `defs` 里定义、用 `use` 引用，可编辑版会展开成形状组。

规整步骤统一两件事：箭头一律换成标准三角（模型自己画的 marker 常被二次旋转成「<」）；没有铺满画布的底色时补一块白底（否则图片版白底、可编辑版透出母版底纹）。

助手写长 SVG 时注意一次输出完整代码块；过长可按层分段写再合并，并以 `svg_diagram.py check` 为准。

## 代码在哪

`scripts/diagram/`：`catalog`（风格版式目录）→ `palette`（色板）→ `sizing`（字号）→ `prompt`（拼提示词给助手，模板 `prompts/diagram/generate_svg.md`）→（助手写 SVG）→ `normalize`（规整）→ `checks/`（检查）→ `render`（PNG）→ `svg_parse`（SVG 转图元）→ `to_ooxml`（图元转形状）→ `place`（写进幻灯片）。`pipeline` 是三个任务脚本共用的出图流程（读助手已写好的 .svg、检查、两版、报告）；**无 generate 调模型环节**。

## 卡片完整性、等宽与对比度（硬性）

- 结构图内并列的标题式标签/页签/同级标题条须**单行平铺**，宽度兼容本组长名（等宽取最长）；卡片正文可多行，固定区卡片标题可折行，导航式标题名不可折。
- 并列/能力/流程卡须有标题+至少一行说明，禁止空壳卡（`card_title_body`）。
- 同一行对等节点（流程、时间轴、并列卡，含强调色末卡）宽度须一致（`peer_equal_widths`）；表格式名列/内容列允许不等宽。
- 标题用主色或明显更深字色，正文用近黑深色；可用色带标题条、编号块区分层级；禁止标题与正文同为浅色（`contrast_hierarchy`）。
- 重点词在 brief 中用【】标出，绘制时去掉括号并以 tspan 主色加粗。
